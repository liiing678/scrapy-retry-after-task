Scrapy 下载槽 Retry-After 冷却的行为约定

起点与实现范围
基于 scrapy/scrapy 的 2.13.3 标签，Git commit 155a504f24b9dd180b8786a4fa709f87cfe8fb66。初始代码未修改。变更应进入现有 Scrapy 下载、重试、设置和文档体系，保留相应许可证。task_materials 是自建的本地输入与检查，不是上游功能实现，也不声称来自上游问题报告。

配置
RETRY_AFTER_ENABLED，布尔值，默认 False。
RETRY_AFTER_MAX_DELAY，有限且非负的秒数，可为小数，默认 120.0。开启功能时错误配置须在采集开始前明确报错，不静默转换成无上限等待。0 表示所有有效头计算出的额外冷却均为0。
RETRY_ENABLED=False 时冷却不生效。不开启本特性时，原版行为、重试统计、下载延迟和公开接口保持兼容。

响应资格与解析
在实际 HTTP 下载完成时，response.status 属于 RETRY_HTTP_CODES 且请求没有真值 dont_retry，才考虑建立冷却。不要求当前请求还剩重试机会；耗尽次数的响应仍可能约束该槽后续请求，但不能创造额外重试。响应是否被其他中间件进一步处理不撤销已经建立的服务端冷却。
Retry-After 字段必须恰好一个值。去除两侧 ASCII 空格和制表符后，接受只含 ASCII 数字的非负整数秒，或合法的 IMF-fixdate HTTP 日期，如 Wed, 21 Oct 2015 07:28:00 GMT。日期中的逗号不是多值分隔符。可以额外兼容历史 HTTP 日期形式，但不能把任意文本当日期。多条 Retry-After 头、空串、带正负号数字、小数、NaN、无穷大和无法解析的日期均忽略，不新增等待、不抛出影响采集的异常。特别大的整数秒应按上限封顶，不得溢出崩溃。
对于日期，在收到响应时按当前 UTC 墙钟换算剩余秒；已过期日期和数字0均得到0。本题不以服务端 Date 头修正时钟偏差。将非负时长限制到 RETRY_AFTER_MAX_DELAY，再转换为稳定的等待截止时间。一次等待开始后，墙钟调整不能导致冷却提前结束或无限延长；测试使用可控时钟验证这一点。
解析语义参考 RFC 9110 第10.2.3节（https://www.rfc-editor.org/rfc/rfc9110.html#name-retry-after）；重复值及上限是本题明确的产品约定。

槽与时序
使用请求此次实际下载对应的槽键，包括自定义 request.meta['download_slot'] 和 CONCURRENT_REQUESTS_PER_IP 的现有映射。一个槽的冷却不能直接暂停另一个槽。所有已经进入下载器且有正常并发余量的其他槽请求应继续执行；不要求改变现有调度器的跨域优先级或全局队列公平性。
在下载器收到有效响应之后，同槽尚未开始的网络传输必须被拦住，包括该槽早已排队的请求。已经开始的传输不取消，也不因为它在冷却期间完成而延后交付响应。若它又给出新的有效限流时长，以该响应收到的时刻重新计算候选截止时间，槽截止时间取已有与候选的较晚者。
没有有效限流头的响应不清除既有冷却。暂时空闲的槽在截止时间前不能因垃圾回收丢失冷却。其他槽的相同网址主机也不必共享显式指定的不同槽；同槽的不同网址主机则应共享冷却。

与既有等待和生命周期的关系
下一次启动时间应同时满足普通下载间隔和冷却截止时刻，也就是两种约束中较晚的时刻。保持 DOWNLOAD_DELAY、RANDOMIZE_DOWNLOAD_DELAY 和 AutoThrottle 更新延迟的原有意义，不能累加两个完整等待，不能将冷却时长写回 slot.delay，也不能在到期后持续保留额外节流。验证精确合并时关闭随机延迟；开启随机延迟时验证其既有范围与冷却下界。
使用非阻塞等待，不通过 time.sleep 或同步忙等阻塞事件循环。冷却到期后能继续队列，不丢请求，不重复发出同一请求，不额外增加 retry/count。
Downloader.close() 返回后，本特性引入的等待回调均已取消，不得再启动网络请求；正常采集结束时没有新增悬挂定时器或未处理异常。本题不要求改变现有 close_spider 对在途请求的正常等待语义，也不要求跨进程保留冷却状态。

公开验证与补充检查
task_materials/acceptance.py 对本地 HTTP 请求的观察是新增功能检查。它在初始版本上应发现冷却缺失；不能为使检查通过而修改探针站点的限流响应、断言或预期值。可以新增测试文件。
必须覆盖：默认关闭；整数秒；HTTP日期；无效/多值头；单次上限；同槽排队和重试受限；不同槽不被阻塞；多个在途响应延长但不缩短等待；重试次数耗尽、dont_retry和RETRY_ENABLED；DOWNLOAD_DELAY与AutoThrottle兼容；空闲槽存续；关闭清理。
本地集成检查使用毫秒级记录并允许明确的采样容差，容差只处理计时误差，不能把提前发出的请求算作合格。墙钟变化、空槽回收与关闭时序适合用 Twisted 的受控时钟或等效机制单独测试，不强制具体私有方法名或内部数据结构。已有回归命令和补充人工验收步骤列在 README.txt 中。
