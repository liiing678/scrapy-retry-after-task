# HTTP 缓存的 Vary 变体

在本仓库现有 HTTP 缓存链路中扩展能力。源码起点为 Scrapy 2.13.3；目标功能尚未实现。`scrapy/downloadermiddlewares/httpcache.py` 管理命中、重验和异常恢复，`scrapy/extensions/httpcache.py` 提供策略与持久化。交付应包含源码变更、回归测试，以及设置和迁移行为的文档。

## 开关与兼容范围

新增布尔设置 `HTTPCACHE_VARY_ENABLED`，默认 `False`。关闭时保留原有缓存行为、存储接口与上游回归测试；开启后支持 `FilesystemCacheStorage`（含 `HTTPCACHE_GZIP=True`）和 `DbmCacheStorage`。DBM 使用标准库 `dbm.dumb` 验证，不依赖平台独有的 gdbm。

继续以 crawler 的 `request_fingerprinter.fingerprint(request)` 作为基本键。变体区分仅发生在 HTTP 缓存内部；不得通过改动全局指纹、请求 URL、请求正文或去重器实现。现有自定义指纹器、方法/正文的隔离、不同 spider 的隔离保持有效。第三方存储适配不是本次范围；公开的 `open_spider`、`close_spider`、`store_response`、`retrieve_response` 调用方式不变。

## 变体选择与持久化

1. 收集响应全部 `Vary` 头行，按逗号拆分；字段名去掉首尾空格/制表符、转为大小写不敏感的集合、忽略空成员并去重。集合顺序不同不代表不同规则。没有 Vary 或仅空成员表示空集合。
2. 对每个字段，从发出该响应所对应的请求中取得 `Headers.getlist()` 的值序列。每个值只去掉首尾 SP/HTAB，其余字节与顺序保持；不合并多值、不按逗号重排，也不把值转换为小写。缺失字段与存在但值为空不同。未列入 Vary 的头不影响命中。
3. 一个基本键可保存多个选择值组合；保存新组合不覆盖同集合下的其他变体。关闭、重新创建并打开中间件/存储后，选择结果不变。有效期按变体独立判断，继续遵守 `HTTPCACHE_EXPIRATION_SECS`；刷新一个变体不能延长另一个变体的存储期限。
4. 一个基本键只保留最近一次处理的响应所声明的字段名集合。如果可存储的网络响应改变集合，整组旧变体失效，再保存当前变体。无 Vary 与有 Vary 相互切换也按此处理。这里“最近”指 `process_response` / `store_response` 的调用顺序；不要求跨进程并发写入，也不需要按源站 Date 排序。
5. 任一 Vary 成员为 `*`，该响应不建立可复用缓存，并使同基本键已有的整组缓存失效。其他基本键不受影响。启用开关时，两种内置策略和两种存储均遵守此规则；`HTTPCACHE_ALWAYS_STORE` 不能覆盖它。
6. 没有匹配变体就是未命中，不得先取另一变体再发送其 ETag/Last-Modified。`HTTPCACHE_IGNORE_MISSING` 对未匹配请求仍抛出原来的 `IgnoreRequest`；下载异常也不得回退到另一变体。匹配变体的原有异常恢复规则保持不变。
7. `dont_cache` 请求直接绕过查询、保存与失效；RFC 策略的 `no-store` 保持原有不存储行为。除星号以及已公开的集合替换规则外，不增加整组清理要求。

不规定磁盘索引或记录结构，不要求强制断电时的事务恢复、多个爬虫进程共享同一目录、清理全部历史孤立文件或无界规模性能指标。必须实际持久化，不能用进程内字典替代重启恢复。

## 304 重验

以下新增行为适用于开启开关且使用 `RFC2616Policy`。`DummyPolicy` 的新鲜度判断不改。

过期的匹配变体可以发送其原有条件头。收到 304 时，返回该变体的原状态码、URL 和正文，保留 `cached` 标记；将 304 提供的端到端响应头按字段整体替换到旧响应，未提供的保留。包括 Date、Cache-Control、Expires、ETag、Last-Modified、X-Revision 与 Vary。不合入 Connection、Keep-Alive、Proxy-Authenticate、Proxy-Authorization、TE、Trailer、Transfer-Encoding、Upgrade 以及 Connection 头列出的字段；Content-Length 沿用原正文对应的旧值，304 的空正文及长度不得覆盖它。此次合并不要求处理旧 Warning 头的额外清理。

合并后按原策略判断可存储性和新鲜度。允许存储的合并结果必须持久化，并刷新该变体的存储时间；如果合并头声明的有效期尚未耗尽，下一次请求以及重开存储后的请求应直接命中，而不是再次发出条件请求。`max-age=0`、`no-cache` 或 Age 已超过有效期的副本仍需重验。`no-store` 合并结果不写入持久化缓存，本题不额外要求删除原条目，星号规则除外。304 不带 Vary 表示沿用旧集合；显式空 Vary 表示空集合；可存储的合并结果显式改成另一集合时旧组失效，再以当前请求的选择值保存。304 的 Vary 含星号时，本次仍返回旧正文，随后不得再复用该基本键。

对网络 200 的保存和 304 重验使用相同的变体选择口径。测试用的 Vary 字段均为普通请求头，不包含由缓存新增的条件头；不要求支持 Vary: If-None-Match / If-Modified-Since 的特殊组合。不改变其他中间件的压缩、重试或重定向职责。

## 旧缓存

开启开关后，固定上游版本写出的无 Vary 缓存仍可读取；旧条目含非空 Vary 时，允许直接安全未命中，两种存储行为一致，不得猜测选择值、返回错误变体或报反序列化异常。任务附带 `legacy_seed.py` 只按上游旧格式写出合成输入，和新格式的布局无关。无需支持把新格式缓存交回旧版本软件读取；关闭开关时也不能把变体记录当作无 Vary 旧记录误读。

## 验收

所有条件在本文公开。随附测试是可运行的覆盖样例，不是全部需求的替代；可以新增测试，不能删改样例来降低条件。

| 行为 | 输入与检查 | 结果 |
| --- | --- | --- |
| 同址多版本 | 中间件真实请求 `/article` 的 en/CN、zh/CN、en/US，再重访 | 三份正文独立，重访不增加源站请求数 |
| 选择值规范 | 大小写/重复 Vary 字段、SP/HTAB、空值、缺失、多值顺序 | 按上面定义命中，未列入的头无影响 |
| 持久化及隔离 | 关闭重开、不同方法/正文、spider、自定义指纹 | 正确命中且不串键；文件、gzip 文件、DBM 一致 |
| 重验 | `/revalidate` 连续读取三次，再重开缓存 | 网络状态依次 200、304，后续直接命中；正文完整且刷新头生效 |
| 规则变更 | 顺序保存新集合；304 显式改集合或星号 | 旧组失效，其他基本键保留 |
| 边界与兼容 | 星号、dont_cache、ignore_missing、过期、旧格式 | 行为与本文一致，未匹配变体无条件头和错误回退 |
| 原有能力 | 运行上游 HTTP 缓存、请求与指纹回归 | 关闭开关不改变原有行为 |

源站是本题自建的确定性夹具，所有请求只访问本机；它不是目标功能的实现。需同时检查正文、响应头、源站访问记录与重开后的结果，不能以新增单元测试通过替代上述持久化和真实 HTTP 检查。
